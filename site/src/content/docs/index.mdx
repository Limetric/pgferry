<section class="hero-recommendation">
	<p class="eyebrow">Real migrations, no surprises</p>
	<h2>Introspects your source schema, creates matching PostgreSQL tables, and streams data — then adds keys, indexes, foreign keys, sequences, and triggers after the load.</h2>
	<p>For most migrations, that covers the entire pipeline end to end. When something can't be migrated automatically — views, routines, generated-column expressions, or unsupported index types — <code>pgferry plan</code> tells you before any data is touched. No surprises, no black box.</p>
</section>

## Two valid approaches, both easy

Both are a single config file. Fast is great for dev iterations and works fine for production when you can afford to re-run from scratch. Safe adds crash recovery and validation for when you can't.

<div class="config-compare">
	<div class="config-compare-col">
		<p class="config-compare-label">Fast</p>
		<div class="config-panel">

```toml
schema = "app"
on_schema_exists = "recreate"

[source]
type = "mysql"
dsn = "root:root@tcp(127.0.0.1:3306)/source_db"

[target]
dsn = "postgres://…/target_db?sslmode=disable"
```

</div>
		<p class="config-compare-note">Drops the target schema, skips WAL logging, and optimizes for speed. Ideal for disposable dev or staging targets you rebuild often.</p>
	</div>
	<div class="config-compare-col">
		<p class="config-compare-label">Safe</p>
		<div class="config-panel">

```toml
schema = "app"
on_schema_exists = "error"
unlogged_tables = false
resume = true
validation = "row_count"

[source]
type = "mysql"
dsn = "root:root@tcp(127.0.0.1:3306)/source_db"

[target]
dsn = "postgres://…/target_db?sslmode=disable"
```

</div>
		<p class="config-compare-note">Refuses to overwrite existing schemas, keeps WAL logging for crash safety, checkpoints progress, and validates row counts after the load.</p>
	</div>
</div>
